# 可直接执行的 Goal 开发提示词

目标是让 Coder 不必猜任务范围或完成条件。详细、精确、步骤可执行；复杂度决定长度，约束不能因压缩消失。本 Skill 写提示词，不自动启动 Coder、提交或发布。

## 输入和输出
输入项目背景、目标目录/环境、需求计划/AC、当前 Goal/Git 基线、工程方案、冻结/可写边界、用户操作授权、验收反馈（如有）。独立使用也可：把输入中的明确需求转换成最小 AC，不强制其他 Skills 已安装。
输出一份可直接复制的 Coder 提示词；必须有具体动作、期望结果、验证入口和停止规则。可附一份交接信息表（Task-ID、输入版本/指纹、depends_on、write_set、AC-ID、命令、证据、approval、retry_budget）；这只是接口设计，不宣称调度器已实现。

## 编写步骤
1. 先对输入作一致性检查：目标目录是否存在、基线是否实测、已确认/假设/阻塞是否分清、当前权限是否支持任务。只读检查实际可获得的信息；未知 HEAD 写“实现前只读核验”，新目录写“无仓库/无基线”，不得捏造 Commit、测试通过或版本号。
2. 选择完整 Goal、增量功能、定向修复或发行任务模式。完整 Goal 使用 [Goal 提示词模板](assets/goal-development-prompt.md)，定向任务可合并章节，但保留目录/基线、范围、实施、AC、允许/禁止、测试证据、失败/停止和报告。
3. 把功能写成编号操作。每步说明修改入口、依赖/前置、页面或 API 行为、数据影响、错误/取消/禁用、AC 与验证。核对执行该步所需产物已经存在或可在其写集内创建，不能只有无环依赖而实际顺序不可执行。复杂异步写明开始、锁定、终态、刷新/重启恢复和旧结果取消；统计和列表不得各造数据。
4. 写实际 UI/交互和数据/状态要求；无 UI、无数据库或无需截图的任务明确不适用及替代证据，不为凑模板引入功能。DEMO 和真实实现边界单独说明；既有冻结代码只允许任务要求的兼容扩展，禁止整体重构。
5. 明确路径级允许修改、禁止修改和操作权限。依赖升级、全局配置、外部服务、Git 写入、部署/发布分别看现有授权；提示词不能授予输入没有的权限。本次禁 Git 的限制不自动传播为其他项目永禁 Git；未来提交冻结仍需明确控制点。
6. 给命令或明确的运行接口：工作目录、工具/环境前提、实现时应创建的脚本、执行顺序、成功退出码、测试对象、证据路径。区别拟定命令与实测命令；不要输出一个不存在的脚本并暗示它已可运行。已选技术栈使用自身工具，不能所有项目一律 pnpm/Playwright。
7. 用 [精确写作与异常规则](references/writing-guide.md) 检查每条 AC：正常、异常、权限/边界、取消无副作用、状态关联、兼容/恢复至少覆盖实际相关项。测试不能只验证按钮出现；不能用直接 store 操作替代用户链路，也不能禁用失败断言换绿灯。
8. 定义证据与报告。证据绑定候选基线及工作区内容指纹、步骤、环境、实际结果、日志/截图路径；UI 有多个目标视口时按实际要求检查。报告按模板列变更、AC、命令、证据、受保护范围、Git、风险和状态。需要状态/验收产物时使用 [状态模板](assets/project-status.md) 和 [验收模板](assets/acceptance-record.md)。
9. 写有限返工与停止条件：默认同一问题最多 2 次有针对性的修复，整体最多 3 轮验证；用户已有预算优先。每次保留失败信息、说明修复原因；未知环境问题不无限安装、换栈或扩大范围。遇需求阻塞、授权不足、越界、数据破坏风险或达到预算时停止依赖任务，报告可继续部分，不把测试失败标完成。
10. 明确完成后停在“已完成，待外部 Reviewer 验收”。不进入下一 Goal，不自动冻结，不把自测当外部通过。单个 Coder 应能独立完成实施与自测，不能依赖尚未提供的多 Agent 调度器；独立 Review 另由有授权的审查者进行，Coder 自检不得冒充独立结论。删掉最终提示词中未替换的模板占位符；若关键决策仍阻塞，输出标为“草案，不可派发”，列问题而不是伪装成最终命令。

## 完稿门槛
完整任务的 16 项有内容或合理不适用：背景、目录、环境栈、Git/Goal 基线、目标、功能步骤、页面交互、数据状态、允许修改、禁止修改、测试运行、截图证据、完成标准、失败处理、报告、完成后停止。每个关键 AC 能定位到步骤和测试；环境无法证实的不写已通过；权限继承不扩大；复杂任务可独立复制执行，无须读聊天历史。

## 使用示例
“使用 $goal-prompt-writer，根据采购 DEMO 计划和 Goal 0 方案生成 Coder 提示词；禁止 Git 写操作，完成后待验收。”应指定可运行基座、断网验证、模拟边界和重置隔离。
简单修复也要明确：“在已核验基线中修正弹窗取消后仍写入的问题；只改相关动作与必要回归；点击取消后记录、审计和指标均不变；运行该链路和原确认回归并留证；失败两次停止；报告变更、证据、Git与限制；待外部验收后停止。”最终稿还须填真实目录、基线和项目命令。
