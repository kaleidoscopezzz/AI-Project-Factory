# 架构选择与基础门槛

## 按部署和真实性决策
| 场景 | 可行方案 | 选择依据 | 不可偷换 |
| --- | --- | --- | --- |
| 离线演示 Web | 静态 SPA + 确定性数据 + 本地资源；需要附件/大数据可选本地服务+SQLite | 展示目标、目标设备、存储容量、交付启动方式 | 演示账号不等于真实认证；离线不等于离线安装开发工具 |
| 多人真实企业 Web | UI + 服务端 API + 关系数据库；按团队能力选单体/分层 | 事务、并发、资源授权、审计、维护成本 | 不把浏览器缓存当权威存储；禁止服务不可用时转 Mock 成功 |
| 桌面/移动 | 原生或跨平台 UI + 本地/远程存储 | 设备 API、平台分发、同步与离线需求 | 不强制 Web 菜单或 Windows 便携包 |
| CLI/后台服务 | 命令或 API、结构化日志、单元/集成测试 | 无 UI、协议、部署与运维 | 截图可不适用，但输出、退出码、健康/日志证据不可省略 |

不要由行业名称推导技术栈。选择一个够用的方案；未要求微服务、消息队列、付费云或 AI API 时不主动引入。

## 基础纵向样板
最少串通入口→输入验证→动作→存储/事务→读取→错误→证据。可选虚构“基础样例记录”，不提前实现采购审批或库存出入库。样板入口标“工程验证”，后续移除/保留策略明示。先冻结接口，再交给业务增量开发。

## 状态不变量
- 模板不可变、运行状态独立；列表/详情/指标/审计同源。
- 对取消动作无写入；异步返回必须核对操作版本/取消标志，不能覆盖重置后新状态。
- 正在执行需要明确可见的开始和终态，不预置永久运行记录以假装功能。
- 模拟时钟只在演示需求成立时采用；真实项目使用明确服务端时区/时间语义。
- DB 迁移和 seed 幂等，真实系统的破坏性 reset 限隔离开发测试库并校验环境；不得擦掉用户数据以修测试。

## 验证取舍
每个重要不变量至少一个可失败的验证：未经授权的直接 API 请求、重复提交、刷新/进程重启、取消无变化、存储失败、迁移幂等。无需为纯文本或目录创建镜像测试。UI 用 Playwright 或平台对应框架；后端按语言用原生测试框架和真实隔离 DB，不能只 Mock 掉数据库。

断网 DEMO 应阻断外部域名但允许本地服务。真实企业项目记录已声明 API/DB 请求，预期的业务拒绝可列白名单；意外错误必须归零或获得明确豁免。不统一要求所有 HTTP 请求都 200。

交付可先有开发运行说明，真正便携打包或生产发布由后续阶段验收。正式包从固定候选源码构建，记录版本/哈希/依赖和目标设备实测；未测平台如实列限制。
