# 可运行的 Goal 0 工程方案

本 Skill 产出工程方案，不自动开发业务，也不替用户采购服务。用户明确要求实现骨架时可把方案交给 Coder，但先完成当前授权的输出。

## 输入/输出
输入需求计划（或原始需求）、目标工作目录、现有工程状态、目标运行/部署环境、用户技术偏好、数据真实性与操作限制。缺需求计划时做最小范围整理，不要求其他 Skill 已安装。
输出使用 [工程模板](assets/goal0-blueprint.md) 的完整 Goal 0 方案：技术决策与理由、模块目录、契约、纵向样板、实施顺序、可执行命令约定、验收与证据映射、后续扩展点、阻塞条件。方案中的命令是 Coder 应建立并验证的接口，不是假称已运行的结果。

## 工作流程
1. 识别 Web/服务端/桌面/移动/CLI、DEMO/真实系统、单机/多人、离线/在线、数据规模与部署约束；已有工程先核实已有基础和冻结边界，优先增量。
2. 读 [架构选择与基础门槛](references/architecture.md)，比较最少两个可行方案并选一个。优先用户已选栈和现有生态；记录替换触发条件。区分本机开发依赖、运行依赖、发行依赖，版本由实现时实际核实并锁定，不复制参考项目版本。
3. 定义目录、模块依赖方向、共享组件和装配者。模块有独立路由/服务/数据适配入口；状态来源唯一，指标从记录派生；禁止后续 Goal 反复重建布局或复制状态机制。
4. 给 UI 项目指定视觉 token（颜色、字号、间距、密度、焦点/对比度）、主页面、菜单、导航、空/加载/错误/禁用/确认态、视口与键盘路径。样板要真实可交互、可刷新；没有图表需求不强制驾驶舱或双主题。无 UI 项明确“不适用”及替代证据。
5. 身份区分未登录/已登录/过期/无权限。DEMO 明示模拟，不能声称安全授权；真实项目由服务端校验身份和资源权限，浏览器隐藏按钮不是安全边界。明确账号初始化、凭据配置和审计脱敏。
6. 数据定义 ID、状态机、校验、关联、异步生命周期和时区。区分模拟适配器与真实 API/DB，不能静默 fallback。指定持久化失败、迁移、初始化、重置和恢复；真实生产数据不能提供前端一键清空，重置仅限明确隔离的开发/测试环境。
7. 工程配置覆盖锁文件、环境变量示例、启动/停止、端口占用、构建、类型/格式/静态检查、测试框架与干净初始化。真实后端增加迁移、seed、事务/唯一性和健康检查；核对模型定义→迁移→seed 的依赖和写集。涉及静态资源时，生产模式验证明确资源由谁提供，不能用开发服务成功替代。只做一条最小纵向样板，不提前实现所有业务。
8. 给各基础 AC 指定测试层级及证据：交互走 UI，授权走 API，持久化查 DB/存储和重启，UI 证据标版本/视口/步骤。记录日志、失败请求、预期错误与意外错误，不能把应返回的 401/403 计成“测试必须没有任何 HTTP 错误”。
9. 写 PROJECT_STATUS 与验收记录产物要求，包含当前 Goal、基线、已完成/阻塞、实际命令/结果、限制、下一步、外部验收状态；门槛未过不叫完成，过自测后仍待外部验收。Git/打包/发布遵守本次授权，不从模板推导授权。

## 自检与示例
自检 14 项：项目类型、栈、目录、视觉交互、框架导航、身份权限、数据状态、Mock/真实区别、持久化初始化重置、配置运行构建、自动测试、状态管理、证据、验收门槛全部有明确方案或合理不适用理由。Goal 1 有可定位的增量入口，基础能独立跑通。

“使用 $goal0-scaffolder 为断网采购 DEMO 做 Goal 0 方案”：可选静态 SPA + 确定性虚构数据，说明前端身份只是演示。
“使用 $goal0-scaffolder 为多人库存管理做基础方案，必须真实数据库”：应输出 API/DB 纵向链路、服务端授权、迁移和环境隔离，不能拿 localStorage 替代数据库。
