# 虚构案例 B：真实后端企业管理系统

请规划“澄明设备运营公司库存与领用管理系统”。公司与业务需求完全虚构；未来工程需要真实后端和关系数据库。

## 已确认需求
- 30 名内部员工，多个用户同时工作；开发机 Windows，目标部署为公司内网 Linux 服务器。允许本机容器开发，发布上线属于后续审批阶段。
- 仓管员维护物料并执行入库/出库，员工提交领用申请，部门经理审批本部门申请；系统管理员管理账号和角色。
- 用户只能访问其部门的领用申请；仓管员的库存处理权限与普通员工区分。真实服务端必须校验身份及资源权限。
- 领用获批不立即扣库存，仓管员执行出库时扣减。库存不得为负；重复请求不重复扣减；两个并发出库竞争库存时结果必须保持一致；所有成功变更有操作审计。
- 需要真实数据库持久化、初始化迁移、虚构开发测试 seed、备份恢复方案。浏览器缓存不允许作为权威库存数据。
- 员工关闭浏览器、应用服务重启后已提交数据仍保留；后端或数据库不可用时清楚报错，不能静默换 Mock。
- 界面覆盖登录、主布局、物料台账、领用申请、审批、库存处理、审计入口；内网桌面浏览器目标视口为 1440×900 与 1280×720。
- Goal 0 只建 UI/API/DB 基础纵向链路、真实账号认证、最小资源权限、健康检查和工程样板记录；实际物料/申请/审批/出入库业务分后续 Goal。
- 不引入付费云、真实身份平台、短信/邮件发送、支付、AI 模型 API 或微服务调度。

## 尚未确定
企业 SSO、跨部门代办、审批授权代理、生产备份保留周期、生产容量目标和实际部署凭据未提供；不能直接作生产上线承诺。开发环境用本地账号且不接真实身份服务可作为明确工程假设，生产身份方案待确认。
