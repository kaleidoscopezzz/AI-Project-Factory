# 案例 A：公共设备采购申请演示系统需求计划

版本：case-a-plan-1；日期：2026-10-08（Asia/Shanghai）。唯一需求输入：[input.md](input.md)。这是独立 Skill 文档行为验证产物，不是系统实现或测试通过记录。

## 定位、事实与边界

用户明确：面向现场方案演示人员，在单台 Windows x64 电脑的浏览器断网展示虚构采购流程；现场无管理员权限，不安装 Node/Git/包管理器。填报员、审批员均为模拟身份，不使用真实政务数据，不提供真实认证、法定审批或合规结论。

范围：工程基础、申请填报与提交/退回、审批意见、执行进度、同源统计和操作记录、两个演示场景、刷新保留及确认重置。阶段交付从可运行基础递进到业务闭环，正式现场包装单列最后阶段。Goal 0 仅实现带身份切换、布局、导航、持久化与重置的工程样板。

排除：真实政府账号、预算平台、支付、电子签章、采购法规判定、多人并发、生产服务器、复杂 Agent 调度。不得把菜单占位当成业务完工。

可撤销工程假设：React + TypeScript + Vite 单页应用、IndexedDB 保存虚构运行数据、本地 SVG/CSS 资源、npm 管理依赖、Vitest 与 Playwright 分层测试。理由与替换条件见 [goal0-blueprint.md](goal0-blueprint.md)。假设不构成行业业务规则。

目标目录为 `C:\FactoryCases\ProcurementDemo`，存在性、工具版本和 Git 基线尚未核验。本轮不创建目录。未来 Coder 的首项任务只读核验，不能捏造已有 HEAD。
