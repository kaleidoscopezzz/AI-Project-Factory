# 已验证能力与批准范围

这份公开摘要依据批准 Tag、既有真实执行报告和正式阶段回执整理，不公开本地原始运行位置、线程标识或私人日志。本次只核对既有资料，没有新增模型调用或业务 E2E。

## APF 里程碑

| 阶段 | 批准范围 | 仍需区分的限制 |
| --- | --- | --- |
| Goal 0 | 三个 Codex Skills、模板、离线 DEMO 与真实后端/数据库规划案例 | 两个案例仅为规划行为验证，未开发业务系统；全局 Skills 自动发现未实测 |
| Goal 1 | 真实 Planner→TaskPacket→Coder、基础检查及恢复；新需求 Full Access 与 CodexPath 整改 | 新需求 Full Access 入口的新增控制验证使用替身，不能冒称全新入口真实 E2E |
| Goal 2 | Tester、Reviewer、DefectPacket、有限返工与恢复实现，经外部有限范围批准 | 真实 Tester 已运行；该阶段真实 Reviewer 批准与模型自动返工闭环未验证；三条非关键归档引用仍 warning/unverified |
| Goal 3 | 原待办软件的已批准 Goal 0 接续至独立 Goal 1，真实开发、Tester、只读 Reviewer 与阶段回执 | 受控两阶段，不是任意 Goal 全自动；真实返工闭环仍未验证 |

Goal 3 后续取得真实 Reviewer 批准，不会追溯改写 Goal 2 当时的限定范围或失败结果。原始失败账本与历史验收材料保留。

## 验证性质与下一步

Goal 3 封版时确定性回归 260/260；它验证控制逻辑和兼容性，不能替代真实业务链路。Coder 初次开发内的自测修复不等于 CoderRepair 自动闭环，真实返工调用没有使用。

Full Access 无 OS 隔离，Token 无硬上限，换机完整 E2E 未验证。软件是单进程本机离线案例，不代表生产系统或任意项目的通用能力。正式路线图下一步为 [Goal 4 受控 Git](MULTI_AGENT_ROADMAP.md)，尚未开发。

## 阶段记录如何保存

同一软件项目在 `control/sequence/` 保存阶段配置、游标、前序批准来源快照和阶段完成回执。后续阶段在 `control/goals/goal-1/` 保存独立包、执行及质量记录；业务源码在同一 `workspace/` 增量演进。批准绑定候选及必要文件 SHA，旧失败结果保持其原始性质。公开摘要不要求读者重建私人验证环境。
