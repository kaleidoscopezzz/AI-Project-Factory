# 已验证能力与批准范围

这份公开摘要依据批准 Tag、真实执行报告和正式阶段回执整理，不公开本地原始运行位置、线程标识或私人日志。历史里程碑批准范围保持原貌，后续产品验收另行区分。

## APF 里程碑

| 阶段 | 批准范围 | 仍需区分的限制 |
| --- | --- | --- |
| Goal 0 | 三个 Codex Skills、模板、离线 DEMO 与真实后端/数据库规划案例 | 两个案例仅为规划行为验证，未开发业务系统；全局 Skills 自动发现未实测 |
| Goal 1 | 真实 Planner→TaskPacket→Coder、基础检查及恢复；新需求 Full Access 与 CodexPath 整改 | 新需求 Full Access 入口的新增控制验证使用替身，不能冒称全新入口真实 E2E |
| Goal 2 | Tester、Reviewer、DefectPacket、有限返工与恢复实现，经外部有限范围批准 | 真实 Tester 已运行；该阶段真实 Reviewer 批准与模型自动返工闭环未验证；三条非关键归档引用仍 warning/unverified |
| Goal 3 | 原待办软件的已批准 Goal 0 接续至独立 Goal 1，真实开发、Tester、只读 Reviewer 与阶段回执 | 受控两阶段，不是任意 Goal 全自动；真实返工闭环仍未验证 |
| Goal 4 | 授权本地 Git 初始化/Commit、候选与正式质量批准来源绑定，已封版 | 不自动 Tag/Push；真实 Git 集成验证在隔离夹具，不为历史业务项目补建试验 Commit |
| Goal 5 | Release Agent 构建、ZIP 检查、独立解压运行及交付记录，已限定范围封版 | 当前便携包依赖运行环境；不包括通用 EXE、安装器、远端上传或部署 |

Goal 3 后续取得真实 Reviewer 批准，不会追溯改写 Goal 2 当时的限定范围或失败结果。原始失败账本与历史验收材料保留。

六个研发里程碑的核心开发完成不代表 APF 1.0.0 正式发布。CLI 0.1.0 已整合规划、受控双阶段开发和发行接口。新待办需求复用原 Planner/Goal 0 Coder，软件 Goal 0 获得真实 Tester 和独立 Reviewer 批准。早先 Goal 1 的批准交接不足已整改，新的合法接续与实际派发输入预检通过，完整确定性回归 419/419。随后唯一一次 Goal 1 Coder 派发被平台额度限制拒绝，回合未完成、业务源码未变；原调用额度已占用且窗口过期。没有新增 Goal 1 Tester/Reviewer 或新 ZIP。断点复核不自动刷新预算，后续需要明确新增续派授权，继续复用已批准 Goal 0。完整产品验收仍未完成，详见 [产品入口](PRODUCT_USAGE.md)。

## 验证性质与下一步

Goal 3 封版时确定性回归 260/260；它验证控制逻辑和兼容性，不能替代真实业务链路。Coder 初次开发内的自测修复不等于 CoderRepair 自动闭环，真实返工调用没有使用。

Goal 5 封版资料记录完整回归 316/316、最终发行定向 23/23，共 318 个不同测试通过。它们验证控制逻辑与发行机制；真实业务候选另外完成构建、业务/Edge 检查及解压运行。文档同步仅引用既有结果和外部审查结论，本轮没有重新测试。

Full Access 无 OS 隔离，Token 无硬上限，换机完整开发 E2E 未验证。软件是单进程本机离线案例，不代表生产系统或任意项目的通用能力。[Goal 4](GOAL4_USAGE.md) 已按授权本地版本范围封版；[Goal 5](GOAL5_USAGE.md) 已按本地发行范围封版。[CLI 0.1.0](CLI_USAGE.md) 保留仅规划入口，新增 [受控双阶段开发与发行入口](PRODUCT_USAGE.md)；新的真实场景结果见 [当前产品状态](../PROJECT_STATUS.md)，不能拿历史候选冒充新输入全链验收。建议 Goal 6 尚未正式立项。AGENTS.md 强制生成、详细需求忠实度验证、真实自动返工、多模型和多 Agent 自由编排均为未来计划。

## 阶段记录如何保存

同一软件项目在 `control/sequence/` 保存阶段配置、游标、前序批准来源快照和阶段完成回执。后续阶段在 `control/goals/goal-1/` 保存独立包、执行及质量记录；业务源码在同一 `workspace/` 增量演进。批准绑定候选及必要文件 SHA，旧失败结果保持其原始性质。公开摘要不要求读者重建私人验证环境。
